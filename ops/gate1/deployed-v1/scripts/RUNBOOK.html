Gate 1 Measurement Runbook

A no-trade, full-universe market-data measurement. One question: can the FYERS websocket and this harness receive and durably preserve full-mode raw callbacks across Bujji’s authoritative universe?

What changed in revision 3 — capture correctness

  • The corpus now stores an immutable snapshot. Records were queued as a reference to the SDK's own dictionary and serialised later on the writer thread — so what reached the file was not provably what arrived. The record is frozen to a string inside the callback, before the SDK can reuse the object. A test mutates the dict immediately after the callback returns and proves the stored value is the arrived value.
  • Dual clocks. Wall clock for correlating with logs and exchange timestamps; monotonic for every duration. A wall-clock step used to land in the interarrival distribution as a gap that never happened — the control shows a simulated NTP step produces a −3599 s gap on wall clock and exactly 1.0 s on monotonic.
  • Offline replay exists. Previously the corpus was written and never read back except to count parseable lines. gate1_replay.py verifies hash, manifest, accounting and sequence contiguity before analysing, replays in sequence order, and refuses to certify a corrupt, incomplete or unsealed artifact. It runs as part of every session, and a refusal fails Gate 1.
  • Order-book fields are analysed. Bid/ask, sizes, OI, volume and exchange timestamps are now interpreted rather than merely stored. A field the SDK never sends is reported NOT_DELIVERED_BY_SDK — never as zero, which would read as absent market activity.
  • Accounting includes in-flight records. offered == written + rejected + dropped + in_flight. Omitting in-flight made a benign mid-run state indistinguishable from silent loss. At close the strict form must hold.
  • Snapshot failures are their own category — counted as rejected, reason preserved, and fatal to Gate 1. Never silently omitted, which would leave an unexplained sequence hole.

Verified on the host — Sunday 23 Aug, 15:10 IST

  • bujji-options-os-trading — the only unit with a real order-placement call site. Timer disabled; a ConditionPathExists gate blocks execution even if started by hand. Proved by starting it: ConditionResult=no, ExecMainPID=0.
  • bujji-certify-ws-option — inhibited the same way, so no concurrent websocket runs on the same app identity.
  • Live checkout /opt/bujji/app at 2e0509a, clean. The harness and builder run from /opt/bujji/gate1-run/; the universe is built from the architecture worktree /opt/bujji/work-m4.

Harness feed evidence — not Bujji runtime evidence

The single most important thing to carry out of Tuesday. These are different measurements, and this run performs only the first.

What a PASS establishes

  • This host, this token identity, this SDK-boundary harness and this measured universe sustained one bounded session.
  • The FYERS websocket delivered full-mode callbacks, and every one the harness received was frozen at arrival and stored.
  • A verified corpus: hash, manifest, accounting and sequence contiguity all checked by offline replay before any figure is quoted.

What a PASS does not establish

  • That the raw exchange wire frame was captured. The SDK decodes the binary feed before this process sees anything; what it dropped or renamed is not recoverable and is not claimed.
  • That FYERS delivered every exchange tick. There are no broker sequence numbers, so a tick FYERS never sent is undetectable.
  • That the unchanged Bujji runner receives these ticks.
  • That FyersTickFeed receives them — it keeps symbol+ltp and discards the other full-mode fields. That is exactly why this harness binds the SDK directly.
  • That Bujji’s tick journal durably records them.
  • Any runtime strategy safety property.
  • Permission to trade, deploy, merge, push, or enable entry.

Gate 1 fails on any one of these

Seven failure conditions, graded automatically

Any single one is a FAIL. They do not trade off, and a strong result elsewhere does not offset one.

  1. Ingestion loss — the feed delivered a message the corpus does not hold.
  2. Queue drop — the bounded queue discarded anything.
  3. Write failure — a message was accepted but not written (rejected > 0), or raw lines on disk do not match the write count.
  4. Corruption — the corpus fails offline re-parse.
  5. Unsealed artifact — no seal was written, so nothing can be checked.
  6. Partial reconnect restoration — a symbol producing callbacks before the forced reconnect did not produce them after. A vacuous baseline also fails.
  7. Incomplete accounting — offered == written + rejected + dropped does not hold. An unaccounted message is indistinguishable from silent loss.

Silence is coverage. Acks are not data.

A far contract nobody traded produced no callback, so there was no callback to lose. Counting silence as ingestion loss would fail a healthy feed on a quiet morning. Separately: a subscription acknowledgement answers a question about a subscription — it is never evidence that market data is currently flowing.

Restoring trading is a separate, deliberate act

No command in this runbook can enable it. Restoration requires deleting /etc/systemd/system/bujji-options-os-trading.service.d/gate1-no-trade.conf, then systemctl daemon-reload and re-enabling the timer. Creating the sentinel file is not a restore path — it would leave a gate in place that is permanently satisfied and therefore inert, which is worse than no gate because it reads as protection.
