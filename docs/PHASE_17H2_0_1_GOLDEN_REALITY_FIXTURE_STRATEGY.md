# Phase 17H.2.0.1 — Golden Reality Fixture Strategy

**Status: FIXTURE PRESERVATION + STRATEGY DOCUMENT. No
`LiveMarketDataProvider` code. No schema changes. No new dataclasses. No
production runtime changes. No transformation of any captured payload.**

Preserves Gate B's real 2026-08-13 broker observations as immutable test
fixtures before `LiveMarketDataProvider` implementation begins, so future
tests run against real, dated FYERS reality rather than invented shapes.

---

## Part 0 — Audit: existing fixture conventions (verified before deciding anything)

**No `tests/fixtures/` directory existed anywhere in this repo before
this phase.** Confirmed by search — zero matches for `fixtures` under
`tests/` or the repo root.

**The one existing "real data fixture" precedent is a different asset
class, deliberately kept outside the repo tree:**
`tests/test_options_os_runner.py`/`test_trading_brain_runtime.py` both
reference `REAL_BHAVCOPY = "/tmp/m1/BhavCopy_NSE_FO_0_0_0_20260525_
F_0000.csv"` — an **external, absolute path**, not a checked-in fixture.
This is deliberate, not an oversight: NSE bhavcopy files are large,
externally-sourced daily data dumps, a genuinely different size/
provenance class than a Gate B discovery artifact.

**Gate B's artifacts are a different, smaller class of asset** — 672
bytes to 19,462 bytes each, self-contained JSON, generated by this
project's own scripts rather than downloaded from an external vendor.
**Decision: these belong inside the repo tree, at `tests/fixtures/gate_b/`,
as proposed** — diverging from the bhavcopy external-path precedent
deliberately, because the reasoning that justifies keeping bhavcopy
external (size, external vendor provenance) does not apply here.

**No existing safety-scan rule inspects `tests/` content for forbidden
fields.** This project's established `test_*_safety.py` AST-scan pattern
(`test_market_reality_safety.py`, `test_market_timeseries_safety.py`)
targets production packages (`bujji/market_reality/`,
`bujji/market_timeseries/`), never `tests/` itself. No existing mechanism
would have caught a credential accidentally checked into a fixture file —
checked manually instead (Part 1).

**No `.gitignore` exists in this repo at all** (consistent with the
standing, previously-flagged fact that this repo has had no commit since
`b148e39` and is not under active git tracking during this engagement) —
so "committed to git" is not a live concern either way; the fixtures live
on the VPS filesystem exactly like every other file in this tree.

## Part 1 — Sensitivity check (performed before copying anything, not assumed safe)

Before preserving these files unchanged, each was checked for credential-
or account-identifying content — a check the constraint "no transformation"
does not exempt, since redacting a genuine credential would be a safety
requirement, not a forbidden normalization:

```
grep -oi 'token|app_id|account|password|secret|client_id|api_key' <file>
```

**Result: the only match, across all four files, is `fyToken`** — e.g.
`"fyToken": "101126081845094"`. Confirmed by direct inspection this is
FYERS's own **public per-instrument identifier** (appears on every
option-chain and depth row, one per contract symbol), not an account
credential, API key, or access token. No FYERS access token, app ID,
account number, or any other credential appears in any of the four
artifacts. **Safe to preserve byte-for-byte.**

## Part 3 — Fixture layout

```
tests/fixtures/gate_b/
    fyers_india_vix_certification_20260813.json
    fyers_option_chain_discovery_20260813.json
    fyers_websocket_certification_20260813.json
    fyers_depth_discovery_20260813.json
```

**Naming convention:** `<original filename, unchanged>` — deliberately
NOT renamed to something generic like `vix.json`/`chain.json`. The
existing name already encodes source (`fyers_`), content
(`india_vix_certification`/`option_chain_discovery`/etc.), and capture
date (`20260813`) — renaming would discard information for no benefit.

**Directory choice:** `tests/fixtures/gate_b/`, not
`tests/fixtures/<per-script-name>/` or a flat `tests/fixtures/*.json` —
grouped by the **evidence-collection event** (Gate B, 2026-08-13) rather
than by script, because these four files are correlated observations
from one coherent capture session (same day, same token, same market
conditions) and a future second Gate-B-style run (a different day) should
become a **sibling** directory (e.g. `tests/fixtures/gate_b_20260901/`),
never an overwrite of this one — preserving the ability to compare two
real capture sessions against each other later, not just against
invented data.

**How tests should reference them:** by a path relative to the test
file's own location, mirroring the existing
`Path(__file__).resolve().parent` pattern already used in
`test_options_os_runner.py` for locating `config/options_os_shadow.yaml`
— e.g.:

```python
GATE_B_FIXTURES = Path(__file__).resolve().parent / "fixtures" / "gate_b"
OPTION_CHAIN_FIXTURE = GATE_B_FIXTURES / "fyers_option_chain_discovery_20260813.json"
```

Never an absolute VPS path (unlike the bhavcopy precedent) — since these
fixtures are small enough to live inside the repo tree, a relative path
is both correct and portable, which an external absolute path is not.

## Part 4 — Evidence discipline, verified, not just stated

- **Copied unchanged**: `diff -q` (byte comparison) between source and
  fixture confirms zero difference — not just "looks the same," verified.
- **No normalization**: field names (`ask` singular, `oich`, `pdoi`,
  `fyToken`, etc.) are exactly as FYERS returned them and exactly as
  `docs/FYERS_REALITY_PAYLOAD_CONTRACT.md` already documented — the
  fixture and the contract document describe the same, unmodified reality.
- **No field renaming**: in particular, the `ask`-not-`asks` finding
  (17F.1.2/17G) remains visible in the fixture exactly as captured — a
  future test reading this fixture will see the same real inconsistency
  a live provider must handle, not a pre-corrected version that would
  hide the need for that handling.
- **No cleanup**: the underlying/index row's different field set (in the
  option chain fixture), the `oiflag`/`atp`/`tick_Size` fields present in
  the depth fixture, and every other "extra" or "irregular" field
  observed live remain present — nothing was trimmed to "just the fields
  we think we need."
- **No inferred values**: no field absent from a real response (OHLC on
  the option chain fixture, `bid_price`/`ask_price`/`oi` on the websocket
  fixture) was backfilled, interpolated, or synthesized. Their absence in
  the fixture is itself part of what the fixture proves.

## Part 5 — Per-fixture documentation: capture date/source, purpose, what it can/cannot prove, why it's safe for deterministic tests

### `fyers_india_vix_certification_20260813.json`

- **Captured:** 2026-08-13, 09:19:05 IST, live NSE market hours, via
  `scripts/certify_vix_access.py`, `direct_sdk_fyers_broker_py`.
- **Purpose:** ground-truth shape for a `CERTIFIED_AVAILABLE` VIX
  certification result — `quote_status`/`historical_status`/
  `timestamp_valid`/`volume_available`/`oi_available` (the latter two
  correctly `null`).
- **Can prove:** that a test's VIX-certification-consuming code correctly
  reads a real `CERTIFIED_AVAILABLE` artifact shape.
- **Cannot prove:** VIX behavior on any OTHER day, under a
  `PARTIAL_CERTIFICATION`/`NOT_CERTIFIED` outcome (no such real artifact
  exists yet to preserve), or anything about VIX over websocket (this
  script is REST-only).
- **Why safe for deterministic tests:** a static, immutable JSON file —
  reading it twice always produces the same bytes, unlike a live call.

### `fyers_option_chain_discovery_20260813.json`

- **Captured:** 2026-08-13, ~09:19 IST, via
  `scripts/discover_option_chain_premium_fields.py`, 22 real strike rows
  (CE+PE) plus 1 underlying row, `strike_count=5` (default).
- **Purpose:** ground-truth for the `optionchain` endpoint's real field
  set — `ask, bid, fyToken, ltp, ltpch, ltpchp, oi, oich, oichp,
  option_type, prev_oi, strike_price, symbol, volume` on strike rows;
  `description, ex_symbol, exchange, fp, fpch, fpchp, ltp, ltpch, ltpchp,
  fyToken, symbol` on the underlying row. **Confirms the absence of
  OHLC/settlement and of any timestamp field** — a negative fact a test
  can assert against.
- **Can prove:** that a future `LiveMarketDataProvider`/collector's
  row-extraction logic reads the REAL field names correctly, and that
  its handling of "no OHLC available" / "no expiry on this endpoint" /
  "no timestamp available" behaves correctly against a real absence, not
  a synthetic one.
- **Cannot prove:** chain behavior on a different day, at a different
  time of day (this is one point-in-time capture), for a different
  underlying, or at a different `strike_count`. Cannot prove anything
  about the `depth` endpoint's differently-shaped response (separate
  fixture).
- **Why safe for deterministic tests:** static file; also already the
  documented source for the exact same field-name claims in
  `docs/FYERS_REALITY_PAYLOAD_CONTRACT.md` §1 — a test built on this
  fixture and a human reading that document are checking the same
  ground truth.

### `fyers_websocket_certification_20260813.json`

- **Captured:** 2026-08-13, 09:19:34–09:21:44 IST (120-second window),
  via `scripts/certify_websocket_access.py`, `fyers_websocket`,
  `NSE:NIFTY50-INDEX`, full mode (`litemode=False`), 291 real ticks.
- **Purpose:** ground-truth for `PARTIAL_CERTIFICATION` result shape,
  the real `field_census` structure, and the real
  `fields_absent_from_every_tick` list (`ask_price, ask_size, bid_price,
  bid_size, last_traded_qty, last_traded_time, oi, vol_traded_today`).
- **Can prove:** that test code correctly reads a `PARTIAL_CERTIFICATION`
  artifact (not just the `CERTIFIED_AVAILABLE` happy path the other three
  fixtures represent) and correctly distinguishes "field present" from
  "field structurally absent from this spot subscription."
- **Cannot prove:** anything about futures/option websocket ticks (spot
  only, by scope decision); **cannot prove or disprove reconnect
  behavior** (`reconnect=False` in this script, a single clean window —
  restated here because it is the single most likely fact about this
  fixture to be misquoted later, per the standing instruction from the
  prior Gate B execution turn); cannot prove `litemode=True` (production)
  behavior — this artifact is explicitly full-mode.
- **Why safe for deterministic tests:** static file capturing a
  completed, closed observation window — no live socket, no timing
  dependency, safe to assert against repeatedly.

### `fyers_depth_discovery_20260813.json`

- **Captured:** 2026-08-13, ~09:22 IST, via
  `scripts/discover_depth_response_shape.py --option-symbol
  NSE:NIFTY2681824100CE`, futures leg (`NSE:NIFTY26AUGFUT`, auto-resolved)
  and one option leg, two polls each, 5 seconds apart.
- **Purpose:** ground-truth for the `depth` endpoint's real field set
  (`ask, atp, bids, c, ch, chp, expiry, h, l, lower_ckt, ltp, ltq, ltt,
  o, oi, oiflag, oipercent, pdoi, tick_Size, totalbuyqty, totalsellqty,
  upper_ckt, v` — **including the `ask`-not-`asks` finding**), the real
  5-level ladder shape (`{price, volume, ord}`), and the real
  poll-to-poll evidence toward full-snapshot behavior (both raw polls
  are preserved under `raw_responses`, not just the structural report —
  a test can directly compare `futures_poll_1`/`futures_poll_2`).
- **Can prove:** that a future depth collector's field-mapping logic
  (the `ask` → `asks` normalization decided in 17H.1) operates on the
  REAL raw key, and that OI/`pdoi`/`ltt` extraction reads real,
  non-fabricated values matching what `docs/FYERS_REALITY_PAYLOAD_
  CONTRACT.md` §2 documents.
- **Cannot prove:** depth behavior for any OTHER option contract (this
  captured exactly one, `NSE:NIFTY2681824100CE`, chosen because it was a
  real symbol from the option-chain fixture, not guessed); cannot prove
  snapshot-vs-incremental behavior definitively — only two data points,
  5 seconds apart, one session (the script's own conservative framing,
  preserved unchanged in this fixture's `note` fields).
- **Why safe for deterministic tests:** static file; both raw polls
  preserved, so a test can assert the exact poll-to-poll deltas
  (`ltt: 1786593123 -> 1786593128`, etc.) documented in
  `PHASE_17G_GATE_B_REALITY_CERTIFICATION_REVIEW.md` §6.4 without
  re-deriving them.

## Part 6 — What this phase does NOT do

- Does not write any `LiveMarketDataProvider` code.
- Does not add, rename, or remove any Layer 0 taxonomy field.
- Does not define `SpotObservation`/`TickObservation`/`DepthObservation`
  or any other new dataclass.
- Does not touch `bujji/production_runtime/` or any other production
  package.
- Does not transform, normalize, or reshape any captured payload — the
  fixtures are exact copies, verified via `diff`.
- Does not yet write any test that CONSUMES these fixtures — that is
  17H.2.1's job (the implementation plan's §6 testing strategy already
  specifies fixtures "lifted directly from
  `fyers_option_chain_discovery_20260813.json`'s real rows," which this
  phase has now made possible by placing that exact file at a stable,
  relative, in-repo path).

## Part 7 — Recommendation for future Gate-B-style runs

Any future live-evidence-collection session (a second VIX/websocket/
depth/chain run, on a different day) should produce its own sibling
directory (`tests/fixtures/gate_b_<YYYYMMDD>/`), never overwrite this
one — preserving the ability to compare real broker behavior across two
different real sessions, which today's single capture cannot do alone
(explicitly named as a limitation in Part 5 for the websocket and depth
fixtures above). Not authorized or scheduled by this document — a
future decision, when a future Gate-B-style run actually happens.
